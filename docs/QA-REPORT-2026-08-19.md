## 3. 구현 상세

### 3.1 보안 하드닝 (cad0de1)
- **TURN**: `validate_credentials`가 HMAC-SHA1 + 만료 상수시간 검증 (기존엔 expiry만 확인 → 자격증명 위조 가능)
- **Billing**: return_url을 URL 파싱으로 origin 비교 (`warp.ponslink.com.evil.com` prefix 우회 차단), PayPal access_token 60초 여유 캐시
- **시그널링**: SDP 256KiB / ICE 4KiB / Manifest 1MiB 크기 제한 (증폭 DoS 차단)
- **Mesh**: memory 모드 인증 우회를 `PONSWARP_MESH_ALLOW_INSECURE_MEMORY` 또는 debug 빌드로만 허용
- **WASM**: HKDF salt 32B 초과 시 sha256 해시(RFC5869), LZ4 256MiB 상한, ReorderingBuffer lazy 할당(128MiB 사전할당 제거)

### 3.2 1:1 P2P 전환 (6f962ab)
- SenderView: "Receivers N/3" → 단일 Receiver 상태(WAITING/CONNECTED/READY), 배치/대기열 UI 제거
- ReceiverView: QUEUED "Position N" → 단순 WAITING, 하이브리드 배너 제거
- transferStore: `completedPeers/queuedPeers/currentTransferPeerCount/waitingPeersCount` 삭제
- 의존성: postcss 8.5.23 / nanoid 3.3.18 / socket.io-parser 4.2.7 (pnpm audit 5→0)

### 3.3 네트워크 재연결 개선 (729fbbe)
분석 결과 재연결 로직은 기존에 부분 존재 → 실제 갭 3건 수정
- **수신측 `navigator.onLine` 미감지**: Wi-Fi↔LTE 전환/라우터 끊김 시 즉시 재연결 트리거 없음 → `window 'online'` 리스너 추가
- **Sender `online` 복구 불완전**: 시그널링 connect만 하고 방 재참여·전송 재개 안 함 → rejoin + `requestMoreChunks()`
- **수신 UI 상태 미표시**: RECEIVING HUD에 "RECONNECTING..." 배지 추가

### 3.4 인프라 (8400b69, 99d7ecd, a774a74)
- compose: 루트 단일화, healthcheck/restart/depends_on healthy, 볼륨 최소화
- Dockerfile: tini + HEALTHCHECK
- nginx: `limit_req_zone` http 컨텍스트(conf.d)로 이동, `/ws`+`/api/` rate limit, `proxy_next_upstream`
- 배포 스크립트: backend.inc/release.id 존재 검사, 롤백 경로 내성 강화

### 3.5 QA 스크립트 (4df9a90)
- 1MB 전송이 150ms 폴링 사이에 완료되어 progress 미관측 → MATERIALIZED + 전송 크기 ≥90% 시 즉시 통과하도록 수정
